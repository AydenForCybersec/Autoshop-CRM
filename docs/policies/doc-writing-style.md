# Policy: Documentation Writing Style

## Who this is for
Anyone writing or updating docs in this repo.

## Before you start
- Identify audience: `Staff`, `Admin`, or `Developer`.
- Choose the correct docs section.

## Step-by-step
1. Keep language simple and direct (grade 6-8 target).
2. Use exact click-path labels from the UI.
3. Use this section order on task pages:
   - Who this is for
   - Before you start
   - Step-by-step
   - If this fails
   - Done when
4. Prefer numbered steps for workflows.
5. Define jargon the first time it appears.

## If this fails
- If content feels technical, rewrite with shorter sentences and concrete verbs.
- If page mixes audiences, split into separate guides.

## Done when
- A non-technical reader can finish the task without outside help.
- A reviewer can trace each instruction to a real UI element or command.
